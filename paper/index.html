Content Refresh Prioritization:
Validation-Aware Signal & Action Analysis

A public-safe analysis of content-level signals for prioritizing pages for human review. The work combines a transparent heuristic, signal analysis, a Random Forest validation experiment, leakage checks, and a ranked action playbook.

30,000-row anonymized working extract 11 model features Client-grouped validation Decision-support only

Abstract

This study asks whether observable content-level signals can provide useful directional evidence for prioritizing content for human review. The analysis uses the 30,000-row anonymized starter extract supplied for the internship, while the broader release is documented separately as a much larger warehouse snapshot. A transparent Week-4 heuristic was followed by signal analysis and a Random Forest regression experiment using historical content and performance signals to examine engagement rate. The random split produced MAE 3.064889 and R² 0.117171, while the client-grouped split produced MAE 3.333219 and R² -0.050984, showing weaker measured performance when evaluating unseen client groups. The resulting queue is therefore positioned as decision-support for review prioritization, not as proof of causal impact or reliable generalization to unseen clients.

Headline finding: the more conservative client-grouped validation weakened the observed performance substantially. That result is itself useful: it limits how strongly the ranking should be interpreted.

1. Introduction / Problem Statement

Content teams have more pages to review than they can manually inspect with equal attention. The practical question is not "what will Google's algorithm do?" but rather: which content items should a human review first, and what observable signal explains that priority?

The unit of analysis is a content item. The output is a ranked review queue with a score, reason code, and suggested action. A wrong prioritization can waste editorial time or lead a reviewer to spend effort on a page that does not need intervention. For that reason, the system is intentionally framed as a triage aid: a human reviews the evidence before taking action.

3. Methodology

Research design

The initial Week-5 work was a signal/correlation analysis rather than a supervised predictive model. To make the validation question testable, Week 6 introduced a simple Random Forest Regressor to predict the measured engagement rate from the Week-5 signal features. The model used 100 trees with random_state=42.

Final feature set

The model used the following 11 features:

content_age_daysdays_since_last_updateimpressions_90d clicks_90dsessions_90dai_traffic_pctword_count ctravg_positionscroll_ratetrend_pct

Target and baseline

The target was engagement_rate. The Week-4 heuristic baseline was a transparent prioritization score: 40% normalized content age, 30% inverse CTR, and 30% inverse engagement rate. Its measured mean baseline score was 0.772544. Because this score is on a different scale from regression MAE/R², it is reported as a prioritization reference rather than treated as a directly comparable predictive metric.

Validation design

Two validation designs were compared using the same Random Forest setup: a standard 80/20 random train/test split and an 80/20 client-grouped split. The grouped split keeps a client's content on one side of the evaluation boundary, making it a more conservative test of performance on unseen clients.

Leakage audit

The target engagement_rate was excluded from the feature set. Week-4 derived fields — baseline_score, reason_code, and action — were also excluded to avoid circular information. A remaining limitation is that some historical traffic features may be close to the engagement measurement period; a stricter time-aware design would be needed to fully establish temporal leakage control.

5. Limitations & Honest Framing

  • The main experiment uses a 30,000-row anonymized extract rather than the entire warehouse release.
  • The observed relationships are directional and do not establish causality.
  • The client-grouped validation result is weak: R² = -0.050984.
  • The baseline score and model metrics are not directly comparable because they measure different things on different scales.
  • The analysis does not prove that refreshing a page, changing a title, or making an SEO change will improve performance.
  • A stricter time-aware validation would strengthen the leakage audit.
  • The ranked queue is a review aid, not an autonomous content-management system.
Safe claim: the analysis measured directional relationships and produced a decision-support ranking. It does not prove reliable generalization, causal impact, or guaranteed improvement from recommended actions.

Human-review rule

Every ranked item requires human review before action. Reviewers should check the underlying signals and page context and record the final decision.

No-go automation list

  • Automatic content publishing
  • Automatic page deletion
  • Automatic SEO changes
  • Irreversible changes without human approval

Monitoring / retrain triggers

  • Material changes in the distribution of input signals.
  • Worsening validation error on a fresh, appropriately grouped or time-aware evaluation.
  • Changes in content lifecycle or measurement definitions that make historical features less comparable.
  • Repeated reviewer disagreement with the reason codes or ranked priorities.
